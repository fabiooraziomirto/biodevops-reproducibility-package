## Headline conclusions

### 1. Does "OPA-or-SHACL union yield" as currently reported double-count a single behavior?

**Yes, substantially, and it is worse than the one case already found in the qwen3.5:27b/gemma3:27b
write-up.** Two structural field-sharing pairs exist, not one:

- `report.evidence_links` emptiness drives both the OPA `technical_incident_missing_technical_evidence`
  rule (deny *and* policy_action — OPA even duplicates this internally) and the SHACL `hasEvidenceId`
  shape, confirmed via the live `rag_pipeline.run_clinical_guard` code path (not assumption).
- `severity==4 && recommendation != ESCALATE_TO_HUMAN_IMMEDIATE` drives both the OPA
  `severity4_or_death_forced_immediate_human_escalation` rule and the SHACL `severity4_opa_overlap`
  shape — this pairing is in fact **already named as an overlap in the shape's own `sh:message`
  text**, it was simply never surfaced in any paper table.

Applying the corrected classifier to the new sweep, the share of "overlap" cases that are purely
structurally redundant (i.e. would look identical with only one of the two layers present) is:
gemma3:1b 84%, qwen3.5:2b 52%, gemma3:4b 11%, **qwen3.5:4b 93%** (this is the mechanism behind its
reported 100% union yield — same pattern as gemma3:27b, not unique to the 27B pair), gemma3:12b
26%, qwen3.5:9b 62%, **gemma3:27b 88%**, qwen3.5:27b 0% (n too small to matter — only 1 overlap
case total). See `new_sweep_decomposition.md` for the full table.

**Implication for the paper**: the current framing of union yield as "OPA and SHACL together"
overstates how often the two layers act as genuinely independent detectors. A "genuine incremental
SHACL value" column (SHACL-only + non-structural overlap) is a more honest measure of what SHACL
adds beyond OPA; it is included in the JSON outputs (`genuine_incremental_shacl_value`) alongside
the raw union yield, which is retained unchanged (it is a per-case OR and was never literally
double-counted at the case level — the double-counting is in the *interpretation* of overlap as
"two independent layers agreeing", not in the yield arithmetic itself).

### 2. Does the paper's current qwen2.5 "SHACL-only = 0" claim hold?

**No — and not for a field-sharing reason. It is a separate, already-partially-fixed classification
bug**, discovered in an untracked prior investigation
(`si_experiments_2026/priority2_shacl_uniqueness/BUG_REPORT_AND_CORRECTED_RESULTS.md`, dated
earlier today, never integrated into the changelog or paper). `rag_pipeline.generate_risk_report`
unconditionally appends `"clinical_shacl_nonconformance_routes_review"` to `policy_actions`
whenever SHACL is nonconformant; the original `reproducibility_audit.py::model_breakdown` checked
raw `bool(policy_actions)` to decide "did OPA act independently", which the marker always satisfies,
making a nonzero SHACL-only count mathematically impossible regardless of the data. **The fix is
already applied in the live `biodevops_rag/scripts/reproducibility_audit.py`** (present today,
verified by reading the code and rerunning it), but `main_revised.tex` was never updated. This
audit independently reproduces the corrected numbers:

| Model | SHACL-only (paper says) | SHACL-only (corrected, this audit) |
|---|---|---|
| qwen2.5:1.5b | 0/40 | 4/40 (10%) |
| qwen2.5:3b | 0/40 | 6/40 (15%) |
| qwen2.5:7b | 0/40 | 12/40 (30%) |

This directly contradicts `main_revised.tex` lines ~351, ~356, ~360, ~432 (Table
tab:independent-scenario-level and the surrounding prose). **Per your standing instruction, this
is flagged rather than silently corrected — it must be an explicit, called-out change in Phase F,
not folded in as if it were always known.**

Of the corrected qwen2.5 overlap buckets, most are also structurally redundant (12/13, 2/3, 4/10
for 1.5b/3b/7b respectively) — the same evidence_links/severity4 sharing found in the new sweep,
confirming the mechanism is general across both model families and both sweeps, not an artifact
of one dataset.

### 3. Any other undisclosed field-sharing pairs?

Yes, in the CGM extension domain (not used in the arrhythmia scaling sweep, but active code):
`sensor_failure_cannot_be_no_action` (OPA) / `sensor_failure_cannot_be_clinically_normal` (SHACL)
and `missing_glucose_evidence_for_no_action` (OPA) / `missing_glucose_evidence_triggers_review`
(SHACL) are literal duplicate rules on identical fields — not just shared inputs but the same
logic encoded twice. Full detail in `field_map.md`. These matter for Phase B's CGM stress test,
not the current arrhythmia sweep.

### 4. Undisclosed directional asymmetries beyond `concept_severity_undercall`?

All ordinal checks in both domains are under-triage-only **except** the FSCA-without-evidence
rule (both domains), which is over-claim-only — and that asymmetry looks deliberate (FSCA is the
one recommendation whose false-positive cost runs the opposite direction from every other
recommendation). No undisclosed/accidental one-sided check was found. Full table in
`directional_asymmetry_audit.md`.

## What still needs a design decision before Phase F

The "corrected union yield" requested in the task description is, at the per-case arithmetic
level, identical to the raw union yield (OR of two flags cannot double-count within a single
case). What changes is the *narrative*: whether the paper (a) keeps reporting raw union yield and
adds the structural/genuine breakdown as a caveat, or (b) headlines a "genuine incremental SHACL
value" metric instead of raw union yield. This is a framing choice, not a number I should decide
unilaterally — flagging for your review before Phase F.
